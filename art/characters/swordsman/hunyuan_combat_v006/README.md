# Мечник — боевой набор v006

Первый набор для проверки MVP. Существующая модель и текстуры v005 сохранены;
в новой версии перестроены движения, скорректирован кафтан под новые позы.
Это ассет, проверенный в Blender и после повторного импорта, без подключения
к игровому контроллеру и без измерения FPS в движке.

## Файлы

- `swordsman_combat_v006.blend` — редактируемый исходник, облегчённый Solid/Texture, Eevee.
- `SK_Swordsman_Combat_v006.glb` — основной переносимый экспорт, текстуры внутри.
- `SK_Swordsman_Combat_v006.fbx` — дополнительный экспорт с запечёнными анимациями/текстурами.
- Три `swordsman_*_2048.png` — basecolor, tangent normal, roughness.
- `combat_events.json` — предлагаемые фазы, события и окна для кода контроллера.
- `combo_preview.gif` — непрерывное комбо; `animation_set_preview.gif` — все девять клипов.
- Отдельные `<clip>.gif` и `pose_contact_sheet.jpg` — просмотр движений и ключевых поз.
- `spec.json`, `build_receipt.json`, `cloth_correction.json` — задание и происхождение изменений.

11 980 треугольников вместе с мечом, 31 кость, максимум 4 влияния.
Исходник хранит редактируемые квады возле суставов; экспорт явно триангулирован.
Анимации авторские процедурные: траектории кисти/клинка, аналитическое IK конечностей,
запечённое в FK. Это не захваченные движения актёра.

## Клипы, 30 fps

| Клип | Длительность | Поведение |
|---|---:|---|
| `idle` | 2,00 с | Нейтральная стойка с мечом, цикл |
| `run` | 0,60 с | Бег на месте, цикл, активная работа ног и свободной руки |
| `attack_1` | 0,40 с | Диагональ справа налево, небольшой шаг, продолжающееся сопровождение клинка |
| `attack_2` | 0,40 с | Обратный горизонтальный удар; окончание подготавливает замах третьего |
| `attack_3` | 0,667 с | Тяжёлый верхний диагональный удар, перенос веса, фиксация позы около 0,067 с |
| `dodge` | 0,333 с | Короткое снижение корпуса, без кувырка |
| `piercing_lunge` | 0,533 с | Подготовка, выставление острия вперёд, короткая фиксация, возврат |
| `hurt` | 0,233 с | Быстрая реакция и возврат |
| `death` | 1,20 с | Падение назад, неподвижная конечная поза; не зацикливать |

`circular_slash` отложен до этапа 2. Walk и дополнительные действия не включены.
При старте death нельзя зацикливать клип: контроллер должен удерживать последний кадр.

## Контракт для игрового контроллера

**Root неподвижен во всех девяти клипах.** Таз смещается локально для переноса веса
и падения, но это не root motion и не перемещение игрового персонажа.
Дальность/скорость рывка и выпада задаются кодом. Движения стоп/таза в атаках
дают визуальный шаг; дополнительное продвижение персонажа при атаке — решение контроллера.

Комбо использует совпадающие граничные позы:
`idle → attack_1 → attack_2 → attack_3 → idle`.
На стыках первых двух ударов нет возврата в idle. Если серия не продолжается,
контроллер должен смешать recovery к idle/run, а не оставлять персонажа в позе
подготовки следующего удара. Ориентир для первоначального blending — 0,08–0,12 с,
затем настройка по игре. Переход run ↔ idle тоже требует смешивания.

Все времена `combat_events.json` — секунды от начала соответствующего клипа.
Startup/active/recovery, input buffer и dodge_cancel_suggested — исходные настройки
для игрового теста, **не окончательное решение о разрешённом прерывании серии**.
Окно неуязвимости тоже только предложено. Хитстоп, урон, хитбоксы, тряска камеры,
отбрасывание и перемещение не реализованы в файле модели.
Фиксация позы третьего удара — часть движения, а дополнительный игровой хитстоп
следует настраивать с её учётом, чтобы не получить излишне долгую остановку.

Базовая опорная траектория бега соответствует примерно 2,273 м/с при speed scale 1.
Согласовывать скорость проигрывания с фактической скоростью движения, иначе стопы
будут скользить. Формула: animation_speed_scale = movement_speed / 2.273.
Стопы в опорных фазах проверены по траектории голеностопа; физика подошвы не моделируется.
Направление персонажа в исходном Blender: -Y. Ориентацию после импорта в движок
нужно проверить отдельно перед настройкой движения и хитбоксов.

## Выполненные проверки

- `validation/release_glb.json`, `validation/release_fbx.json` — актуальные технические
  проверки финальных экспортов: общий бюджет, UV текстурированных мешей, карты,
  веса, девять клипов, длительности, движение и замыкание idle/run.
- `source_validation.json` — каждый кадр всех девяти клипов: неподвижность Root,
  постоянство крепления меча, высота геометрии над полом, позы на стыках,
  траектория опорной стопы, выборочная геометрическая проверка кафтана/ног.
- `roundtrip_validation.json` — сравнение поз костей и границ меча с .blend после
  импорта GLB/FBX в шести временных точках каждого клипа. Допуск 3 мм.
- `package_manifest.json` — SHA256 окончательных артефактов и доказательств проверок.

Служебная Root направлена горизонтально: это предотвращает автоматическое
соединение Hips с Root при FBX-импорте Blender и сохраняет анимацию таза.
Для FBX использовано запекание с шагом 0,125 кадра без дополнительного упрощения
экспортёром; GLB остаётся основным форматом. Число костей не увеличено.

Проверка одежды: вершины и центроиды граней нижней части кафтана против BVH ног,
знаковое расстояние и лучевая проверка нахождения внутри; допуск проникновения 1 мм.
На финальных клипах подтверждённых проникновений этим методом не найдено.
Область талии выше z=.76 исключена. Это не исчерпывающий тест всех пар граней,
торса/рук или самопересечений и не гарантия для новых поз. Физики ткани нет.

Старые `glb_validation.json`, `fbx_validation.json`, `validation/glb.json` и
`validation/fbx.json` относятся к промежуточным экспортам. Для этой поставки
использовать только `release_*.json` с совпадающими SHA256.

## Что ещё проверяется в игре

Управление и отзывчивость, реальные дистанции, окна попаданий/неуязвимости,
правила прерывания, контакт с врагом, смешивание при поворотах и FPS.
Текстуры остаются проекционными с частично запечённым освещением; хват жёсткий,
индивидуальной анимации пальцев и лица нет. Превью — реальный Blender-рендер,
без игровых эффектов и без проверки импорта в Godot/Unity.
